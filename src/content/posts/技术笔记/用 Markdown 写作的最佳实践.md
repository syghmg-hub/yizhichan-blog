写技术文章久了，发现格式混乱比内容错误更劝退读者。这篇整理一下我自己的 Markdown 规范。

<!-- more -->

## 标题层级

一篇文章只用一个 `#`，放在最顶部（很多编辑器会自动用标题当文章名）。正文里最多用到 `##` 和 `###`，四级以下的标题基本没有存在必要。

## 中英文混排

中文与英文、数字之间加空格，这是最容易忽略的细节：

```text
✅ 正确：使用 Astro 7 搭建博客
❌ 错误：使用Astro7搭建博客
```

## 代码块

代码块务必标注语言，否则没有高亮：

```js
const posts = await fetch('/api/posts')
  .then((res) => res.json());
console.log(posts.length);
```

行内代码用反引号包起来：`npm run dev`。

## 引用与列表

- 无序列表表达并列关系
- 有序列表表达步骤或优先级

> 引用块适合放金句、别人的原话、或者需要强调的结论。

## 图片

图片加 `alt` 文本，既对 SEO 友好，图挂了也还能看懂上下文。

## 结语

规范的目的不是限制，而是让写作时不用纠结格式——**把注意力留给内容本身**。
